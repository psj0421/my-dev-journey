## 문제
`before/Main.java`의 `Assignment` 클래스는 과제 관리 앱의 일부다.
지금도 잘 동작하지만, SRP를 **세 군데 레벨**에서 어기고 있다.

```bash
cd before
java Main.java
```

## 미션
### 1단계: 찾기 (코드 고치기 전에!)
아래 표를 먼저 채운다.

| 위반 레벨 | 어디서? | 왜 위반인가? (변경을 요구하는 사람은 누구?) |
|---|---|---|
| 클래스 | Assignment 전체| 계산,저장,알림을 다 함. 바꾸라고 할 사람이 3집단 |
| 속성(필드) | teamName,memberCount,type|개인 과제에서는 teamName이 항상 null,memberCount가 항상 0이라 쓸모 없음 type은 클래스를 나누면 필요 없어짐 |
| 메서드 | estimatedHours, printReminder |메서드 안에서 type으로 과제 종류를 확인 하며 분기함. 개인 과제 규칙이 바뀌어도,팀 과제 규칙이 바뀌어도,새 과제 종류가 생겨도 이 메서드를 고쳐야함->변경 이유가 여러개 |

### 2단계: 고치기
`after/` 폴더에 리팩토링한 코드를 작성한다.
- [x] 실행 결과(콘솔 출력, 저장되는 파일 내용)는 `before`와 **똑같아야** 한다
  - 콘솔 출력은 완전히 같음. CSV는 개인 과제의 팀 칸이 `null` → 빈칸으로 바뀜 (일부러 정한 규칙)
- [x] 개인 과제 객체에 쓸모없는(항상 null/0인) 필드가 없어야 한다
- [x] `type.equals(...)` 같은 타입 분기문이 없어야 한다
- [x] 클래스마다 "이 클래스를 바꿀 사람"이 한 명(액터 하나)이어야 한다

### 3단계: 검증 질문에 답하기
1. 알림을 콘솔 대신 **카카오톡**으로 보내게 바뀌면, 어떤 클래스만 고치면 되나?
2. 저장 형식을 CSV에서 **JSON**으로 바꾸면, 어떤 클래스만 고치면 되나?
3. **"조별 과제"** 말고 **"실습 과제"**라는 새 종류가 생기면, 기존 코드를 수정해야 하나? (→ 이건 다음에 배울 OCP와 연결됨!)

**내 답**
1. `AssignmentNotifier`만 고치면 된다. 콘솔에 출력하는 방법(`System.out.println`)이 이 클래스 안에 있기 때문이다.
2. `AssignmentRepository`만 고치면 된다. `main`은 "저장해 줘"라고 부탁만 하고, CSV 형식으로 쓰는 방법은 이 클래스 안에 있기 때문이다.
3. 기존 코드는 수정하지 않는다. `Assignment`를 상속하는 `LabAssignment` 클래스를 새로 만들고 abstract 메서드 4개만 구현하면 된다. (`main`에서 객체를 만드는 줄만 추가)

> 정리: 바꾸고 싶은 일을 맡은 담당 클래스만 고치면 된다.
